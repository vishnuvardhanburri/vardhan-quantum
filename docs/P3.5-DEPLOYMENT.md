# P3.5.4 — Production Deployment Evidence

## 1. Architecture Overview

```
                            ┌─────────────────────────────────────┐
                            │         Route 53 / ALB               │
                            │   (latency-based routing policy)     │
                            └──────┬────────────────────┬─────────┘
                                   │                    │
                    ┌──────────────▼──────┐   ┌─────────▼───────────────┐
                    │   us-east-1 Region   │   │  eu-west-1 Region        │
                    │                      │   │                          │
                    │  EKS Cluster         │   │  EKS Cluster             │
                    │  2× t3.large pods    │   │  2× t3.large pods        │
                    │  StatefulSet         │   │  StatefulSet             │
                    │  ┌───────────┐       │   │  ┌───────────┐           │
                    │  │ pq-shield-0│       │   │  │ pq-shield-2│          │
                    │  │ 8080/8081  │       │   │  │ 8080/8081  │          │
                    │  │ HB:18080   │       │   │  │ HB:18082   │          │
                    │  └────┬───────┘       │   │  └────┬───────┘          │
                    │  ┌───▼───┐           │   │  ┌───▼───┐                │
                    │  │ pq-   │           │   │  │ pq-   │                │
                    │  │ shield-1│         │   │  │ shield-3│              │
                    │  │ HB:18081│         │   │  │ HB:18083│              │
                    │  └─────────┘          │   │  └─────────┘            │
                    │  Cross-region HB mesh │   │  Cross-region HB mesh   │
                    └──────────────────────┘   └─────────────────────────┘
```

Each region runs an independent `pq-shield` StatefulSet with 2 replicas.
Nodes in both regions exchange heartbeats via UDP across VPC peered /
Transit Gateway-connected clusters. Region tags propagate through the
heartbeat mesh, enabling region-aware leader election and failover.

## 2. Resource Sizing

|-----------|----------:|---------:|----------------------------------|

### 2.3 Latency Profile (measured via P3.5.3 cross-region test)

| Metric                    | Value    | Notes                          |
|---------------------------|---------:|--------------------------------|

## 3. Deployment Procedure

### 3.1 Prerequisites

```bash
aws eks update-kubeconfig --name <cluster> --region <region>
kubectl auth can-i create secret
aws kms list-keys --region <region>
```

### 3.2 Deploy to us-east-1

```bash
./scripts/aws_deploy_region.sh us-east-1 pq-shield-ue1
```

The script will:
1. Validate AWS identity and KMS key in `us-east-1`
2. Update kubeconfig for the `pq-shield-ue1` EKS cluster
3. Create `pq-shield-kms-us-east-1` and `pq-shield-admin-us-east-1` secrets
4. Apply the `us-east-1` slice of `regional-deployment.yaml`
5. Wait for `pq-shield-ue1` StatefulSet to become Ready (300s timeout)

### 3.3 Deploy to eu-west-1

```bash
./scripts/aws_deploy_region.sh eu-west-1 pq-shield-euw1
```

Wait 10 seconds after eu-west-1 deployment completes for cross-region
heartbeat discovery to propagate between regions.

### 3.4 Verify

```bash
# Check pod health
kubectl get pods -n pq-shield -l "topology.kubernetes.io/region=us-east-1"
kubectl get pods -n pq-shield -l "topology.kubernetes.io/region=eu-west-1"

# Check cross-region membership
kubectl exec -n pq-shield -it pq-shield-ue1-0 -- \
  curl -s -H "Authorization: Bearer $(kubectl get secret pq-shield-admin-us-east-1 -n pq-shield -o jsonpath='{.data.token}' | base64 -d)" \
  http://localhost:8081/api/v1/cluster/peers | jq .

# Verify region-filtered endpoint
kubectl exec -n pq-shield -it pq-shield-ue1-0 -- \
  curl -s http://localhost:8081/api/v1/cluster/peers/region/eu-west-1 | jq .
```

## 4. Runbook

### 4.1 Regional Outage Response

| Step | Action                                                                 | Owner         |
|-----:|------------------------------------------------------------------------|---------------|
| 1    | Confirm primary region pods are down via `kubectl get pods`           | SRE           |
| 2    | Confirm cross-region health via `curl .../api/v1/cluster/peers`       | SRE           |
| 3    | Route 53 failover (latency-based routing automatically redirects)     | SRE (manual)  |
| 4    | Scale eu-west-1 StatefulSet to 3 replicas for extra capacity           | SRE           |
| 5    | Update upstream load balancer target group to eu-west-1 only            | SRE           |
| 6    | Monitor `Total E2E Failures` metric in CloudWatch                       | SRE           |

### 4.2 Node Restart / Recovery

After restarting a crashed pod:

1. The pod self-registers with region tag via `VARDHAN_REGION` env.
2. Neighboring nodes receive its heartbeat and update `apply_heartbeat`.
3. Dead → Healthy transition is automatic (fresh heartbeat with newer timestamp).
4. Verify with:
   ```bash
   kubectl exec -n pq-shield -it pq-shield-ue1-0 -- \
     curl -s http://localhost:8081/api/v1/cluster/peers | \
     jq '.nodes[] \| select(.node_id=="pq-shield-ue1-1") | .state'
   # Expected output: "healthy"
   ```

### 4.3 KMS Key Rotation

```bash
# Enable or trigger rotation
aws kms enable-key-rotation --key-id <key-id> --region <region>

# To force immediate rotation (disables old, creates new):
aws kms create-key --region <region> --description "pq-shield KMS key (rotated $(date))"
NEW_KEY_ID=$(aws kms list-keys --region <region> --query 'Keys[-1].KeyId' --output text)
kubectl create secret generic "pq-shield-kms-<region>" \
  --from-literal="kms-key-id=${NEW_KEY_ID}" \
  -n pq-shield --dry-run=client -o yaml | kubectl apply -f -
kubectl rollout restart statefulset/pq-shield-ue1 -n pq-shield
kubectl rollout status statefulset/pq-shield-ue1 -n pq-shield --timeout=300s
```

### 4.4 Ledger Audit

```bash
# Export ledger from a region
kubectl cp -n pq-shield pq-shield-ue1-0:/data/ledger/ledger.jsonl /tmp/ledger-ue1.jsonl
kubectl cp -n pq-shield pq-shield-euw1-0:/data/ledger/ledger.jsonl /tmp/ledger-euw1.jsonl

# Verify with pq_verify
./target/release/pq_verify --ledger /tmp/ledger-ue1.jsonl --ledger /tmp/ledger-euw1.jsonl
```

## 5. Rollback Procedure

### 5.1 Rollback to Previous Image

```bash
# Set image back to previous tag
kubectl set image statefulset/pq-shield-ue1 \
  pq-shield=vardhan-quantum/pq_shield:v3.4-latest \
  -n pq-shield
# For eu-west-1
kubectl set image statefulset/pq-shield-euw1 \
  pq-shield=vardhan-quantum/pq_shield:v3.4-latest \
  -n pq-shield

# Wait for rollback
kubectl rollout status statefulset/pq-shield-ue1 -n pq-shield --timeout=300s
kubectl rollout status statefulset/pq-shield-euw1 -n pq-shield --timeout=300s
```

### 5.2 Regional Rollback

If eu-west-1 is unhealthy and must be rolled back:

```bash
# Scale eu-west-1 to 0 (traffic fails over to us-east-1)
kubectl scale statefulset/pq-shield-euw1 --replicas=0 -n pq-shield
sleep 5  # dead-node reaping

# Verify all traffic routes through us-east-1
kubectl get endpoints -n pq-shield pq-shield-ue1-lb -o jsonpath='{.subsets[*].addresses[*].ip}'
```

### 5.3 Full Rollback (P3.4)

If P3.5 features must be completely disabled:

```bash
# Remove region env var and KMS protector
kubectl set env statefulset/pq-shield-ue1 VARDHAN_REGION- -n pq-shield
kubectl set env statefulset/pq-shield-ue1 VARDHAN_KEY_PROTECTOR=local-dev -n pq-shield
kubectl set env statefulset/pq-shield-ue1 VARDHAN_KMS_KEY_ID- -n pq-shield

# Re-apply P3.4 manifests
kubectl apply -f deploy_pack/k8s/ -n pq-shield
```

## 6. Security Considerations

- **KMS key policy**: Only the pq-shield IAM role in each region
  has `kms:Encrypt/Decrypt` on the CMK. Cross-region access is deny-by-default.
- **Vault file encryption**: The node identity vault is encrypted with
  data-key encryption (KMS-wrapped DEK). Even if the PVC is compromised,
  the identity cannot be recovered without KMS access.
- **Admin token**: Unique per region, stored as a Kubernetes secret.
  Rotate via `kubectl create secret ... --dry-run=client -o yaml | kubectl apply`.
- **Ledger integrity**: Each region's ledger is independently verifiable.
  Cross-region ledger comparison via `pq_verify` detects any tampering.
